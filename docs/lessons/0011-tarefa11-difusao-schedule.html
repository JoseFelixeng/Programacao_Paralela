Tarefa 11: Difusão e Agendamento OpenMP

Teoria

Nesta tarefa, exploramos a difusão 3D (FTCS). O desafio principal é paralelizar loops aninhados (i, j, k) eficientemente.

  • Collapse: Une múltiplos loops em um único espaço de iteração, melhorando o balanceamento de carga e reduzindo o overhead do escalonador.
  • Scheduling: static é previsível (bom para cargas constantes), dynamic adapta-se a variações (bom para desbalanceamento), guided é um meio-termo.
  • Memory Bound: Estênceis 3D acessam muita memória. Em alta concorrência, o barramento de memória torna-se o gargalo, não a CPU.

Prática

Analisamos que o uso de collapse(2) em grades 512³ saturou o paralelismo de forma eficiente. O gargalo observado em 8 threads (queda de eficiência) confirmou que o problema é limitado pela largura de banda da memória, onde adicionar mais threads apenas aumenta a contenção no barramento de dados.

Referência Rápida

  • #pragma omp for collapse(n): Lineariza 'n' loops aninhados.
  • schedule(static, chunk): Divisão fixa de trabalho.
  • schedule(dynamic, chunk): Threads pegam novos blocos conforme terminam.
  • clock_gettime(CLOCK_MONOTONIC): Medição precisa de tempo.
